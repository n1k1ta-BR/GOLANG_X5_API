# Сервис заказов

Учебный REST API на Go для создания заказов, изменения их статусов
и просмотра истории. Данные хранятся в памяти и теряются после
перезапуска приложения

## Запуск

Требуется Go 1.22 или выше.

Команды выполняются из корня проекта, где находится go.mod:

```bash
go mod download
go run ./cmd/api
```

По умолчанию сервер работает по адресу http://localhost:8080

Другой адрес можно задать переменной HTTP_ADDR:

```bash
HTTP_ADDR=:8081 go run ./cmd/api
```

## API

| Метод | Путь | Назначение |
| GET   | /health | Проверка доступности |
| POST  | /api/v1/orders | Создание заказа |
| GET   | /api/v1/orders | Список заказов в порядке создания |
| GET   | /api/v1/orders/{id} | Получение заказа |
| PATCH | /api/v1/orders/{id}/status | Изменение статуса |
| GET   | /api/v1/orders/{id}/history | История статусов |

Пример тела запроса для создания заказа:

```json
{
  "items": [
    {
      "name": "Чай",
      "quantity": 2,
      "price": 100
    }
  ]
}
```

Успешный ответ имеет код 201

Цена задаётся целым числом в минимальных денежных единицах,
например в копейках. Название товара не должно быть пустым или
состоять только из пробелов. Количество и цена должны быть положительными
Заказ должен содержать хотя бы одну позицию

Новый заказ получает статус new и начальную запись в истории

Допустимые переходы:

- new → processing
- new → cancelled
- processing → completed
- processing → cancelled

completed и cancelled являются конечными статусами
Повторная установка текущего статуса запрещена

Пример тела запроса для изменения статуса:

```json
{
  "status": "processing"
}
```

## Ошибки

400  Некорректный JSON, данные, ID или неизвестный статус 
404  Заказ не найден 
409  Запрещённый переход статуса 
500  Внутренняя ошибка 

Пример ответа:

```json
{
  "error": "order not found",
  "code": "ORDER_NOT_FOUND"
}
```

Внутренние детали ошибок записываются в лог и не возвращаются клиенту
Если передан пустой статус, он проверяется до поиска заказа

## Swagger

После запуска сервера:

http://localhost:8080/swagger/index.html

После изменения аннотаций обновить документацию + перезапустить сервер:

```bash
go run github.com/swaggo/swag/cmd/swag@v1.16.4 init -g cmd/api/main.go -o docs
```


## Архитектура

- cmd/api: создание зависимостей и запуск сервера
- internal/order: модели, предметные ошибки и интерфейс репозитория
- internal/handler: HTTP-маршруты, JSON, middleware и обработка ошибок
- internal/service: валидация, расчёт стоимости, статусы и история
- internal/repository/memory: хранение заказов в памяти


Каждый запрос логируется через slog с полями method, path,
status, duration и request_id. Идентификатор запроса также
возвращается в заголовке X-Request-ID

Recovery перехватывает панику, записывает её в лог и возвращает
JSON 500, если отправка ответа ещё не началась
